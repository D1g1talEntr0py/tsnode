# Change Report

## Summary And Scope

This report covers 58 changed project paths: 56 tracked paths plus two added configuration files. The report itself is a separate new artifact and is not included in that total. A read-only audit using Git path inspection and a Node link/path check verified that all 58 paths are represented and every linked workspace path exists. The working tree contains changes from both the user and the assistant; without per-hunk authorship records, it would be inaccurate to describe every change below as assistant-authored. In particular, [scripts/build/build-types.ts](scripts/build/build-types.ts) includes user work. The added [tsconfig-validation configuration](tsconfig.validation.json) supplies strict checking for tests, benchmarks, build scripts, and configuration files.

The main goals were to fix correctness issues in CLI execution, signal handling, config parsing, transform-cache identity/publication, API lifecycle ownership, watch shutdown, and IPC backpressure; to preserve requested modern API behavior; and to make validation cover files that the previous source-only TypeScript check missed. Some changes are runtime fixes, some are approved modernization/API work, some only satisfy newly enabled type checking, and some belong to the user's edits. Those categories are called out below rather than treating every diff as a bug fix.

Only this report was created for the report task; no source, test, existing documentation, or configuration file was modified. Read-only Git inspection (`diff`, status/show/path listing) and a Node inventory/link check were used to audit the report. No commit, dependency operation, test, build, or fresh benchmark was run while preparing it.

## What Changed And Why

### Runtime And Public APIs

- [src/cli.ts](src/cli.ts): centralizes the first-positional-argument scan so option values are not mistaken for the entry path; forwards inherited Node execution flags only when their semantics can be retained; routes `import.meta.main`-sensitive entries through a real process entry point; and preserves native `--print` behavior by forking. It applies the separate `--no-cache` and `--tsconfig` settings before importing the graph. These preserve Node semantics where dynamic import or an in-process approximation would change them.
- [src/run.ts](src/run.ts): fixes inherited Node parent-process flags while filtering eval payloads and duplicate preloads. This does not add or alter IPC environment forwarding.
- [src/run-in-process.ts](src/run-in-process.ts): exposes the loader-inheritance setup for reuse and explicitly checks whether the optional `execArgv` property was supplied, using a shared helper for the defaulting logic. The actual fix is to keep inherited V8 flags governed by the CLI forwarding gate; an explicit empty array was already truthy and is not claimed as previously ignored. The default Worker forwarding mechanism predates the audited delta and is not claimed as wholly new here.
- [src/run-eval-in-process.ts](src/run-eval-in-process.ts): removes the in-process `PRINT` vmString execution path while retaining in-process ESM evaluation, and shares the inherited-argument handling. Virtual eval sources already existed; their introduction is not claimed as new.
- [src/preflight.ts](src/preflight.ts): removes global overrides of `process.listeners()` and `listenerCount()`, preserving their native signatures and behavior, including `listenerCount(eventName, listener)`. It counts other registered handlers locally instead. The removed override unconditionally subtracted one for `SIGTERM`, which could return `-1` after all listeners were removed; the fix does not claim that Node or another library's native optional-argument behavior was avoided. A suspected swallowed-`SIGTERM` hang was probed and disproved, so it is not reported as a fixed bug.
- [src/repl.ts](src/repl.ts): calls `syncBuiltinESMExports()` after patching the relevant built-in API so named ESM imports observe the updated binding.
- [src/utils/path-utils.ts](src/utils/path-utils.ts): broadens detection of `import.meta.main` in entry expressions while avoiding unrelated literal-text false positives. This path also contains user edits; the report does not assign all its hunks to the assistant.
- [src/remove-argv-flags.ts](src/remove-argv-flags.ts): contains user/mixed work in the argument normalization area. Its role is to remove runner-specific flags without consuming neighboring Node-option values; no authorship claim is made for every change in this file.
- [src/api/index.ts](src/api/index.ts): reuses equivalent `tsImport` scopes through bounded hot lookup while retaining successful scopes for late imports. Failed scope construction is cleaned up and concurrent lookups are handled without tearing down successful registrations. This intentionally preserves native module lifetime behavior; successful scopes and Node's ESM module cache are not unloadable.
- [src/api/register.ts](src/api/register.ts): adds a namespace hook dispatcher shared by registrations through `registerScoped`, avoiding per-registration nested closures during resolve/load. Namespace unregister is ownership-safe and idempotent, including stale unregister handles; empty namespace names are rejected. Disposal-capable handles and source-map ownership leases remain requested modern API behavior, not the only changes in this file.
- [src/types.ts](src/types.ts): extends `ParsedTsconfig.compilerOptions` with esbuild-supported raw compiler options and declares the public virtual-source and disposal-capable API surfaces. `virtualSources` is keyed by map identity in scope reuse, so distinct maps do not silently share a scope.
- [src/hook/load.ts](src/hook/load.ts): detects TS/TSX from URL pathnames so fragments such as `.ts#fragment` still transform; keeps raw-annotation detection conservative; routes class fields through the `useDefineForClassFields=false` transform instead of stripping them; and cleans scoped virtual-source lookup keys. Per-registration private config identity serialization prevents stale transform-option reuse. Existing virtual-source support is extended, not newly invented.
- [src/hook/resolve.ts](src/hook/resolve.ts): handles namespace delimiters and fragments without changing delegation for builtins/data URLs, and retains the original error/thrown value where resolution fails.
- [src/hook/utils.ts](src/hook/utils.ts): validates the hook request protocol as JSON and encodes/decodes namespace URLs, supporting the corrected load/resolve behavior.
- [src/utils/tsconfig.ts](src/utils/tsconfig.ts): uses native `JSON.parse` first and falls back to `jsonc-parser` for JSONC, while supporting `extends`, package config resolution, alias precedence, and freshness. Cache identity includes effective configuration contents and relevant compiler identity; this prevents stale alias results after edits. The JSON fast path avoids imposing JSONC parser initialization cost on ordinary JSON configs.
- [src/utils/transform/index.ts](src/utils/transform/index.ts): makes cache identity reflect source, sourcefile, Node/esbuild identity, effective configuration, and custom esbuild options, including RegExp source/flags. Unsupported or JSON-erased option values bypass caching; invalid options get fresh serialization so a warm hit cannot hide esbuild validation errors.
- [src/utils/transform/index.ts](src/utils/transform/index.ts): keys transform identity on source, file path/sourcefile, Node/esbuild identity, effective configuration, and custom esbuild options, including RegExp source and flags. Unsupported or invalid option values bypass cache reuse so esbuild still validates them; custom options are freshly JSON-serialized for identity, not structured-cloned.
- [src/utils/transform/cache.ts](src/utils/transform/cache.ts): publishes versioned JSON records atomically through exclusive temporary files and rename; bounds each in-memory and pending-write tier to 64 entries and 8 MiB; bypasses reads and writes for no-cache mode; and drains bounded batches without discarding overflow. Cold misses avoid repeated exception-driven reads after the cache directory is known absent, while warm disk hits keep direct reads. These are retained budgets and correctness properties, not claimed as newly introduced bounds or zero performance cost.

- [src/utils/temporary-directory.ts](src/utils/temporary-directory.ts): provides validation for the private IPC temporary directory, including mode, symlink, and ownership checks. The cache shares a common base path; private-ownership validation is not claimed as a universal cache-directory check.
- [src/utils/ipc/client.ts](src/utils/ipc/client.ts): bounds frame count and bytes, reserves capacity for control messages, coalesces dependency notifications, and reports overflow rather than silently dropping control state. Disconnect invalidation, timeout, and listener cleanup prevent a stalled or closed parent channel from retaining pending work indefinitely.
- [src/utils/ipc/server.ts](src/utils/ipc/server.ts): tracks owned sockets and listeners so normal close cleans them up, and validates private directory ownership. Foreign-owner permission coverage is privileged and was skipped in the recorded suite.
- [src/watch/index.ts](src/watch/index.ts): waits for readiness before treating a child as watchable, cleans up failed starts, and makes shutdown idempotent with bounded child termination. Already-exited children and signal exits are handled without waiting forever or reporting a misleading success status.

## Mistakes, Revisions, And Rejected Approaches

- An early bounded cache-write approach evicted pending work to satisfy a queue limit. That silently left much of a 301-module wave unpublished and made warm enum runs dramatically slower. It was replaced with bounded batch draining that retains all writes. The final design still bounds retained memory; it does not drop required persistence work.
- Loading the JSONC parser unconditionally imposed substantial cold initialization overhead. The parser is now reached only when native JSON parsing fails, retaining JSONC support without charging ordinary JSON configurations for it.
- An eager cryptographic hash path added startup cost. Hashing was changed to fast FNV bucket selection, with exact identity verification retained. This is not a claim that FNV alone is collision-safe.
- Two raw-buffer/offset cache identity layouts were tested and removed after paired measurements regressed the controlled baseline. The JSON record format and exact verification were preserved.
- Earlier cleanup removed non-performance API modernization the user explicitly wanted retained: disposal handles, source-map ownership, and public `tsImport` virtual-source identity. Those capabilities were restored and covered. They must not be represented as unwanted extras in the final state.
- A suspected signal-swallowing hang was not confirmed by the signal probe. The confirmed preflight defect was the global listener API override and its handling of missing-event results; the report separates evidence from that disproved suspicion.
- A suspected signal-swallowing hang was not confirmed by the signal probe. The confirmed preflight defect was the global listener API override and unconditional subtraction for `SIGTERM`, which could produce `-1` with no remaining listeners; the report separates that defect from the disproved hang.

These reversals are implementation mistakes and course corrections, not unavoidable costs of the final behavior. The user-edited experiment files under `/tmp/tsnode-verified-pairs/unverified/` (the `cache` and `index` experiments) were left untouched and are outside the workspace inventory.
